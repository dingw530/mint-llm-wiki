# 产品规格：Jev 实验性接入（路由与记忆分类）

变更标识：`2026-09-19-jev-experimental-integration`

## 背景

TypeSafe 的 Jev（System One）是一个不生成文本的模型：输入一个 `state` 和一组有类型的 `questions`，直接返回结构化的 `choice` / `score` / `noul` 与 `probabilities` / `confidence`。它的定位恰好对应 Mint 里两处"把 LLM 当分类器用、再把生成的文本解析回代码"的实现：

- `routingService.llmClassify` 让 LLM「只返回 Agent ID」，把返回内容 `.trim()` 直接当 agentId，并**硬编码 `confidence: 0.85`** —— 因为 LLM 根本没提供置信度。
- `memoryService.isConversationValuable` 用问候语集合加 `SELF_REF_PATTERNS` 正则启发式判断"这段对话值不值得长期记忆"。

两处都在做"快速、结构化、代码可直接分支的直觉判断"，正是 Jev 的目标场景；而现有实现分别付出了"假置信度"和"脆弱正则"的代价。

## 目标

把 Jev 作为**默认关闭的实验性功能**接入 Agent 路由与记忆门控两条链路：

1. 两条链路的判断入口抽象为可替换的 provider，Jev 实现与原有实现互不耦合；
2. 开启时走 Jev，关闭或 Jev 不可用时完全走原有实现，存量行为不变；
3. 在设置模块既有的「实验性功能」中提供开关与参数配置入口。

## 范围

**包含：**

- 路由链路：Jev 作为分类来源参与 Agent 选择，其置信度作为第二决策轴。
- 记忆链路：Jev 作为**前置门控与分类打分**来源，决定"是否值得记忆"以及分类与重要度；`content` / `value` 的生成仍由原有 LLM 路径完成（Jev 不能生成文本）。
- 设置界面「实验性功能」中的 Jev 配置区：Endpoint、API Key（加密保存、掩码回显）、模型、路由与记忆两个独立子开关及其置信度阈值。
- 「测试连接」能力：用当前表单值验证配置可用，不写入设置。
- 失败静默回退与审计记录。

**不包含（非目标）：**

- 不替换主对话的流式生成、ReAct 工具轮次、Wiki 页面合并等需要开放文本生成的路径。
- 不改变 Wiki 编译、知识图谱候选生成等其他 LLM 分类调用点。
- 不把 Jev 的 category / importance / action 结果回灌进提取提示词（留待验证价值后另开变更）。
- 不引入数据库 schema 变更。
- 不默认启用 Jev；不因开启实验功能而改变任何默认行为。

## 用户故事

- **US-001**：作为用户，我想在设置里按需开启 Jev 的 Agent 路由，让 Agent 选择在触发词之外也能按语义判断，并在 Jev 不可靠时自动退回原有行为。
- **US-002**：作为用户，我想在设置里按需开启 Jev 的记忆门控，减少无价值对话产生的记忆提取开销，并确保 Jev 失效时记忆功能仍按原样工作。
- **US-003**：作为用户，我想在保存前确认 Jev 配置可用（API Key 有效、Endpoint 可达），并且不想让测试动作污染我的设置。
- **US-004**：作为用户，我不想让这个实验功能拖慢我的对话响应，也不想在 Jev 故障时看到报错或对话中断。

## 业务规则

- **BR-001**：Jev 路由与 Jev 记忆门控是两个独立子开关，可单独开启、单独回退；默认均为关闭。
- **BR-002**：任一开关关闭时，对应链路的行为必须与接入前逐位一致（agentId / confidence / method；是否入队提取）。
- **BR-003**：Jev 路由的置信度低于配置阈值、返回弃权、或答案不在候选表内时，回退原有 keyword / LLM 路由。
- **BR-004**：Jev 记忆门控的"跳过"是终局判决，**不回退** legacy 启发式；只有 Jev 不可用时才回退。
- **BR-005**：Jev 不可用（未配置 Key、网络失败、401、429、529、超时、响应结构不符）一律静默回退，不向用户报错、不中断对话。
- **BR-006**：API Key 加密存储，读取时只返回掩码；前端保存时留空表示继续使用已存 Key。
- **BR-007**：Jev 门控在对话响应结束之后异步执行，不延长单条消息的响应结束时间。
- **BR-008**：Jev 相关的判断与失败必须可审计，用于事后评估实验效果。

## 验收标准

### 配置与开关

- **AC-001**：设置 →「实验性功能」显示 Jev 配置区，包含 Endpoint、API Key、模型、路由子开关、记忆子开关，以及两个子开关各自的置信度阈值；首次打开时两个子开关均为关闭。
- **AC-002**：保存设置后重新打开设置页，Jev 各字段按已存值回显；API Key 以掩码显示，且保存时留空不会覆盖已存 Key。
- **AC-003**：点击「测试连接」用当前表单值发起一次真实 Jev 请求，界面依次呈现"测试中"与成功或可读的失败提示；测试动作不写入设置。

### 路由链路

- **AC-004**：Jev 路由子开关关闭时，路由决策输出的 `agentId` / `confidence` / `method` 与接入前逐位一致。
- **AC-005**：Jev 路由子开关开启、且 Jev 返回达到阈值的 `choice` 时，路由采用 Jev 给出的 Agent，`routing_logs.method` 记录为 `jev`。
- **AC-006**：Jev 返回低于阈值、弃权、或 `choice` 不在候选表内时，回退原有 keyword / LLM 路由，且 `routing_logs.method` 能区分出回退来源。

### 记忆链路

- **AC-007**：Jev 记忆子开关开启、且 Jev 判定不值得记忆时，不入队记忆提取任务，且不调用 legacy 正则启发式。
- **AC-008**：Jev 判定值得记忆时，按原有路径入队提取任务，`content` / `value` 仍由原有 LLM 路径生成。
- **AC-009**：Jev 不可用时记忆门控回退 legacy 启发式，入队与否的结果与接入前一致。

### 降级与审计

- **AC-010**：Jev 调用失败时路由静默回退，用户对话正常完成不中断；失败原因记录到 `routing_logs.method`。
- **AC-011**：每次记忆门控结果写入 `memory_events`，可区分命中、跳过、不可用三种结果并携带失败原因。
- **AC-012**：Jev 记忆门控在 SSE 响应 flush 之后异步执行，单条消息的响应结束时间不因门控而增加。

### 约束

- **AC-013**：不新增数据库迁移；新端点经 `endpoints/` 声明式注册，并可通过 Electron IPC 与 HTTP 两条通道调用。

## 风险与依赖

| 项 | 说明 |
| --- | --- |
| 依赖 | TypeSafe Jev API（`POST /v1/systemone`，Bearer 认证，`model: jev-latest`）。需要用户自备 API Key。 |
| 风险 | **Jev 以英文为训练主语言，其他语言可用但准确率下降**。Mint 的 Agent 描述、记忆分类标签与对话内容多为中文，中文场景下的判断质量未经验证。 |
| 缓解 | 判别指令与选项 key 全部使用英文与 ASCII，中文仅作为待判断的数据出现；置信度阈值默认保守；任何弃权或失败都回退中文原生的既有实现，最坏结果等于今天的行为；审计数据可用于事后量化中文场景的弃权率。 |
| 风险 | `routing_logs.method` 语义从四个枚举值扩展为可能带失败原因的复合串，可能影响未来的消费方。 |
| 缓解 | 该列为无约束 TEXT，当前无 UI 消费方；复合串格式作为契约写入设计文档与代码注释。 |
| 风险 | 开启 Jev 后单次路由最坏情况为"Jev 调用 + 原有 LLM 分类"两次调用。 |
| 缓解 | 关键词精确命中时短路 Jev；Jev 单次约 100ms 且总预算受限；失败与低置信均属预期内的回退路径。 |
| 风险 | 设置保存为全量覆盖语义，旧版本客户端保存设置会把 Jev 开关重置为关闭。 |
| 缓解 | 与 `vectorStore` 等既有字段行为一致，方向安全（回到默认关闭）。 |
