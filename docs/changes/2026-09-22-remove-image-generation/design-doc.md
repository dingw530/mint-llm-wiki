# 设计文档：移除图片生成能力

## 设计决策

采用“删除现行运行时能力、保留历史存储兼容”的收敛策略：

1. 删除图片专用页面、组件、客户端 API、服务端服务和端点定义。
2. 将模型端点统一视为文本端点，移除 active code 中的 `category` 字段和图片分类校验；数据库现有 `category` 列继续保留但不再暴露为产品能力。
3. 消息仓储恢复纯文本消息读写，历史 `messages.image_data` 列不删除，避免修改历史迁移或破坏已有数据库。
4. 会话创建只接受默认文本会话；历史图片会话不会再获得图片专用入口。
5. 重新生成 Electron endpoint manifest，确保 IPC/HTTP 均不包含 `images:generate`。

## 影响边界

| 区域     | 处理                                                                    |
| -------- | ----------------------------------------------------------------------- |
| Client   | 删除 `/image` 路由、图片 feature、图片 API、图片渲染和图片端点配置 UI   |
| Server   | 删除图片 service/endpoint/消息图片路由；仓储和类型去除图片字段          |
| Electron | 由 manifest 重新生成，移除图片 endpoint；保留通用下载能力仅当仍有调用者 |
| Database | 不修改历史 migration；保留旧列以兼容已有数据库                          |
| Docs     | 新增本次收敛变更记录，更新当前架构说明；保留历史图片功能变更文档        |

## 验证证据

- 静态残留搜索：区分当前运行时残留与历史 migration/历史文档例外。
- 单元/集成测试：文本 endpoint、消息仓储、会话和客户端回归。
- 构建产物：manifest 不包含 `images:generate`，client build 成功。
