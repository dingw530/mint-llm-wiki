## 背景与目标

Mint 已有统一 ToolExecutor、服务端策略、一次性工具审批 UI、Zod 输入验证、MCP Adapter、AgentRun 事件和 ReAct 调用预算。当前源码审查发现部分声明没有落实到运行时：`write_file` 的描述承诺审批，但默认元数据不会要求审批；内置 JSON Schema 输出没有统一关闭额外属性；MCP 校验器只实现了 JSON Schema 的部分规则；重试流程没有按副作用风险判断是否可重放。

本变更校准已有安全承诺，并补齐工具参数契约和重试边界。用户可从可见的审批状态判断写操作是否等待授权；非法或超范围输入不会执行；结果未知的副作用调用不会被自动重放。

## 用户与场景

- 个人知识工作台用户要求 Agent 写入 Wiki；用户未批准前，目标文件不得变化。
- 用户拒绝、审批过期或重复提交同一审批时，写操作不得执行。
- Agent 或 MCP Server 提供多余、非法或过深参数时，运行时应拒绝执行并返回可处理错误。
- 工具调用超时或进程恢复时，Mint 需要区分“确定失败”和“副作用结果未知”，避免重复写入或重复外部操作。

## 用户故事

- **US-001**：作为 Mint 用户，我希望所有有副作用的工具都遵守服务端审批策略，从而避免仅凭模型描述就修改 Wiki、文件或外部系统。
- **US-002**：作为工具作者，我希望模型看到的 Schema 与服务端验证使用同一契约，从而拒绝多余字段、非法枚举和越界嵌套。
- **US-003**：作为 Mint 用户，我希望写操作失败或超时后不会被盲目重试，从而避免重复任务或重复副作用。
- **US-004**：作为 Mint 维护者，我希望能按调用 ID 查看工具名、耗时、结果状态和安全参数摘要，从而定位失败，同时不把用户内容和凭证写入日志。

## 范围

### 本次做

- 将审批要求设为服务端工具元数据和策略的明确结果，不依赖 Prompt 或 description。
- 修正 `write_file`、`wiki_ingest`、Bash 高风险操作和所有远程 MCP 调用的审批判定与可见状态。
- 统一 Mint 自有工具 Schema 的封闭对象规则、最大嵌套深度和代码层校验。
- 让 MCP Schema 校验执行受支持 JSON Schema 约束；未知关键约束、外部引用、超深或超大 Schema 失败关闭。
- 将工具执行失败归一为含稳定类别和 `retryable` 的结果，按工具副作用语义控制重试。
- 为一次工具调用提供稳定的 `runId + callId` 身份；写操作重复调用被去重，超时或进程中断后的未知结果不自动重放。
- 接通 ToolExecutor 的结构化审计日志，记录调用标识、工具名、来源、风险、耗时、结果码、错误码、重试次数和经过允许列表筛选的参数摘要。
- 对审计字段做结构化脱敏；默认不记录原始参数值、问题正文、Wiki 内容、文件内容、请求体、凭证或完整异常文本。
- 沿用现有 HTTP/Electron 审批界面和事件协议；补充后端集成与 Chat 浏览器验收。

### 本次不做

- 不增加 tenant、多用户或团队权限体系；Mint 当前按单用户个人工作台设计。
- 不改造 MCP 发现与加载交互，不新增完整策略配置后台。
- 不承诺远端 MCP Server 的 exactly-once 执行；远端不支持幂等键时，结果未知即停止自动重试并交给用户处理。
- 不建设工具级 p99 仪表盘、异常告警或完整数据分析系统。
- 不建设工具级 p99 仪表盘、异常峰值告警或集中式数据分析平台；本次只补运行日志，不把日志等同于监控指标。

## 业务规则

- **BR-001**：审批策略由服务端可信元数据和代码决定；工具描述只能说明行为，不能授权行为。
- **BR-002**：写文件、摄入 Wiki、外部写请求、高风险 Bash 和所有 MCP 调用，在批准前不得进入实际执行函数；远端 `readOnlyHint` 仅是提示，不是授权。
- **BR-003**：审批绑定原始会话、工具名、调用身份和参数摘要；批准只消费一次。拒绝、过期、参数变更或重复消费都不得执行。
- **BR-004**：Mint 自有工具向模型发布的固定 object schema 默认封闭；object 嵌套最多三层；枚举字段必须使用 enum。动态 map 仅可使用显式值 Schema 的 `additionalProperties`，不得使用无约束 `true`。服务端验证不得弱于模型可见 Schema。
- **BR-005**：MCP Schema 必须在注册时通过有界验证器；不支持的 JSON Schema 关键字、外部 `$ref`、超限深度或大小不得静默忽略。
- **BR-006**：模型输入必须先通过 JSON 解析、Schema 校验和工具级跨字段校验；失败不调用工具。
- **BR-007**：工具调用的幂等身份在同一 AgentRun 重试和恢复期间稳定为 `runId + callId`；相同身份最多触发一次有副作用的执行。
- **BR-008**：只有工具策略声明为可安全重试，且失败类别明确可重试时，运行时才自动重试。
- **BR-009**：有副作用的调用在执行开始后超时、断连或进程中断时记为 `tool_outcome_unknown`，禁止自动重放；用户可检查后发起新的调用。
- **BR-010**：权限拒绝、Schema 错误、审批等待、确定失败、超时和未知结果使用结构化结果；保留既有消费者需要的兼容字段，不返回堆栈。
- **BR-011**：每次调用至少产生一个最终结构化日志记录，包含 `invocationId`、工具名、来源、风险、耗时、结果码和重试次数；日志必须接入生产执行路径，不允许依赖未注入的可选回调。
- **BR-012**：审计参数摘要默认只包含字段名、类型、集合数量和字节长度；具体字段值必须由工具级安全允许列表批准。凭证键、URL 用户信息/查询串、请求正文、查询文本、Wiki/文件正文和异常堆栈不得出现在日志中。
- **BR-013**：日志脱敏递归处理嵌套对象和数组；未知或无法安全分类的数据不记录值，只记录其结构摘要。

## 验收标准

- **AC-001（high）**：`write_file`、`wiki_ingest`、HTTP 写方法、高风险 Bash 和所有 MCP 工具在审批前执行次数为 0；只有批准当前一次性调用后执行次数变为 1。拒绝、过期、重放审批不执行。
- **AC-002（high）**：ReAct/SSE 与 Chat UI 将审批等待表示为 `approval_required`；批准后同一调用恢复并完成，拒绝或过期不能显示为工具成功。HTTP 与 Electron 保持同一语义。
- **AC-003（high）**：所有启用的 Mint 自有工具定义通过自动 Schema 检查：固定 object 关闭额外属性、动态 map 有明确值 Schema、嵌套深度不超过三层、固定集合使用 enum；运行时对同一输入实施相同或更严格限制。
- **AC-004（high）**：MCP 校验覆盖 Schema 声明的必填项、类型、enum、字符串/数值约束、数组项、嵌套 object 与额外属性；不支持关键字、外部 `$ref` 和超限 Schema 在工具注册或加载时失败关闭。
- **AC-005（high）**：内置工具的跨字段约束由服务端代码显式校验；JSON/Schema 错误不得进入工具 `execute()`；跨字段错误不得触发检索、摄入任务或其他业务副作用，并返回可读校验错误。
- **AC-006（critical）**：对同一个 `runId + callId` 重复提交、重试或恢复不会重复产生副作用；副作用开始后超时或进程中断会记录为未知结果并阻止自动重放。
- **AC-007（high）**：只有 `retrySafety` 明确允许且失败被标记为可重试的工具调用才会重试；非幂等外部工具不会因通用 `toolMaxRetries` 自动重发。安全重试使用稳定幂等键，并验证调用次数及最终状态。
- **AC-008（medium）**：失败返回稳定错误类别与 `retryable`，不包含堆栈；既有 `error` 字段和审批 UI 消费路径保持兼容。
- **AC-009（high）**：现有只读工具、Wiki 检索、MCP 工具发现、AgentRun 恢复和审批连续性通过相关回归；不得引入 tenant 参数或把 Prompt 作为访问控制。
- **AC-010（high）**：内置及 MCP 调用最终生成结构化日志，至少包含 `timestamp`、`invocationId`、`toolName`、`source`、`riskLevel`、`durationMs`、`resultCode`、`retryCount` 和安全参数摘要；日志在实际 ToolExecutionService 主路径中产生，重试结束后只生成一个 invocation 终态摘要。
- **AC-011（high）**：审计日志不含原始调用参数值、问题/文件/Wiki 正文、HTTP body、凭证、URL 用户信息/查询串或堆栈；嵌套敏感键和值使用 canary 测试证明不会进入序列化日志。参数摘要只保留字段名/类型/数量/长度及显式批准的安全字段。

## 风险与依赖

- MCP Server 的 Schema 方言和关键字实现可能不同；必须记录支持的方言及拒绝原因，并避免以部分校验误报成功。
- 严格关闭 object 属性可能暴露现有 MCP 工具 Schema 兼容问题；应先审计已注册工具定义，再逐个修正本地适配契约。
- 远端副作用与本地 SQLite 无法构成原子事务；本变更采用“未知结果不自动重放”，不宣称分布式 exactly-once。
- 所有 MCP 工具默认要求审批，包括远端声明只读的工具；只读调用的确认次数会增加。本变更不增加本地只读白名单。
- 新增持久化调用状态需要 SQLite migration，并验证旧 AgentRun 数据可继续恢复。
- 现有工具的 `getCallSummary()` 可能含查询内容，不能复用为审计摘要；必须使用独立且默认不暴露值的审计摘要契约。
- 相关历史需求见 [工具运行时安全与 MCP 主动发现](../2026-07-24-tool-runtime-security-discovery/product-spec.md)，本变更处理当前实现与其审批验收承诺之间的偏差，不重做 MCP 发现功能。
