# AgentRun 可恢复持久化与可替换存储产品规格

## 背景与目标

Mint 已具备 AgentRun 生命周期事件的 SQLite 追加日志、顺序校验和中断诊断：服务进程中断后，Reducer 能重建快照，并将未完成工具标为 `tool_outcome_unknown`。但该结果尚未接入用户恢复流程，无法让用户查看中断状态、选择继续/重试/放弃，或处理可能已经产生副作用的未知工具结果。

本变更完成 TD-006 的最小产品闭环：将运行持久化能力抽象为可替换的领域接口，本期只由 SQLite 提供实现；应用重启后，用户可以安全地查看并处理待恢复运行。JSONL 是未来可增加的独立 backend，不是本期存储介质，也不是 SQLite 的双写副本。

## 用户与场景

- 用户在工具调用或模型生成期间关闭应用，重新启动后能看到该运行已中断，而不是把它误认为成功或消失。
- 用户面对未知工具结果时，能看到“结果未知、不会自动重放”的解释，并据此继续安全后续对话、显式重试或放弃运行。
- 用户对同一恢复操作重复点击、页面刷新或网络重试时，不会产生多个恢复运行或重复执行副作用工具。
- 维护者能替换持久化 backend，而不改变 AgentRun、SSE、Electron IPC 或用户恢复语义。

## 用户故事

- US-001：作为用户，我希望在重启后看到曾中断的 AgentRun 及其状态，以便决定下一步。
- US-002：作为用户，我希望对可安全继续的运行选择继续，对失败或中断的运行选择重试或放弃。
- US-003：作为用户，我希望未知工具结果被明确说明；系统未经我确认不得再次执行可能产生副作用的工具。
- US-004：作为维护者，我希望 SQLite 与未来 JSONL backend 遵守同一持久化语义，不让上层业务依赖介质细节。

## 范围

### 本期做

- 定义 AgentRun 持久化领域接口，覆盖追加、读取、开放运行扫描和恢复动作的幂等结果；领域层不得依赖 SQLite 特有类型或 SQL。
- 将现有 SQLite 事件日志保留为本期唯一 backend，并通过 migration 扩展恢复动作、运行快照或必要关联数据。
- 将中断诊断接入应用启动后的恢复列表，以及 HTTP/Electron 的声明式 endpoint；客户端提供恢复状态和继续、重试、放弃操作。
- 为每种工具调用持久化恢复决策所需的最小安全元数据与重放等级：`never`、`requires_confirmation`、`safe_idempotent`。
- 为每个用户恢复动作保存稳定 idempotency key；同一 key 的重复提交返回第一次已确定的结果。
- 明确记录恢复前、恢复后和放弃后的终态/审计状态；保留原始 AgentRun，不以覆盖方式伪造历史。

### 本期不做

- 不实现 JSONL backend、JSONL 导出、SQLite 与 JSONL 双写或自动跨介质迁移。
- 不自动重放任何未完成工具调用；`safe_idempotent` 仅表示可在后续产品策略中被考虑，不能绕过本期确认规则。
- 不持久化 API key、authorization、cookie、原始 prompt、完整思维链、完整工具参数或完整工具结果。
- 不实现跨设备接管、多用户协作、分布式 lease、后台自动续跑或恢复任意流式 token 增量。
- 不改变现有正常运行的 SSE 事件字段、实时审批交互或最终消息保存语义，除非设计文档记录了兼容方案。

## 业务规则

- BR-001：SQLite 是本期唯一被选择和发布的 AgentRun backend；系统不得同时向 SQLite 和未来 JSONL 写入同一运行。
- BR-002：所有 backend 必须保证事件序列连续、终态后不可追加、同一事件幂等重试不重复写入、冲突写入失败。
- BR-003：恢复读取失败、版本不兼容、事件损坏或序列断裂时 fail closed；不得生成误导性的“可继续”状态。
- BR-004：未完成工具必须恢复为 `tool_outcome_unknown`，不得自动转为成功、失败或已取消。
- BR-005：`never` 和 `requires_confirmation` 工具的未知结果必须阻止自动工具重放；用户确认只表达恢复决策，不得被解释为已确认历史工具确实成功。
- BR-006：继续只能从已验证的安全检查点创建新的运行；该新运行必须关联原运行，并保留原运行的中断事实。
- BR-007：重试必须创建新的运行，且不得隐式重复未知副作用工具；需要重新调用工具时，必须满足该工具的确认/安全策略。
- BR-008：放弃是幂等终结动作；放弃后不得再继续同一运行，但历史记录必须可审计。
- BR-009：恢复动作以 `runId + action + idempotencyKey` 去重；相同键必须返回语义一致的结果，冲突键必须明确失败。
- BR-010：持久化 backend 的选择只在应用初始化时确定；运行中不得切换 backend。

## 非功能要求

- NF-001：持久化接口与事件 schema 必须版本化；未知必需事件或不支持版本必须拒绝读取。
- NF-002：恢复列表读取不得调用模型、工具或产生新的副作用。
- NF-003：恢复动作、运行快照和事件 payload 遵循最小数据原则；敏感值只能保存不可逆引用或安全摘要。
- NF-004：用户重复点击、浏览器重连和 Electron IPC 重试不应造成重复副作用，且错误应可诊断。
- NF-005：SQLite adapter 的单次恢复查询和动作提交不得阻塞正常 SSE 流超过既有 SQLite busy timeout 策略；具体性能阈值在设计阶段确定。

## 风险与依赖

- `streamChat`、`reactChat` 与 AgentRun 实时事件链影响面高；实现必须通过 adapter 注入保持现有 SSE/IPC 兼容。
- 当前审批请求存于进程内，重启后不具备继续所需的完整上下文；设计阶段必须决定哪些安全引用或恢复请求需要落盘，不能将敏感原始值直接写入日志。
- “继续”的安全检查点与工具重放等级需要以真实 ToolExecutor/ToolRegistry 语义为准；若无法证明某工具幂等，必须按 `never` 处理。
- JSONL backend 的格式、压缩、导入导出和版本迁移均为后续独立变更，不能成为本期发布前置条件。

## 待确认

- 恢复列表的入口形态：在原会话消息流中以内联卡片展示，还是同时提供独立的运行中心视图。
- 用户对未知工具结果的可选文案与决策集合：本规格保证“无自动重放”，具体是否提供“确认后重新执行”按钮由设计阶段依据工具策略确定。
- SQLite backend 的选择配置是否只保留内部 composition root，或需要为开发/测试公开配置项。
