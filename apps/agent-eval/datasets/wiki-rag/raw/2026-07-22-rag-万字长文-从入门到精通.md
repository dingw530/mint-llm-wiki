# RAG 万字长文：从入门到精通

## 一、为什么需要 RAG —— LLM 的先天局限

向 ChatGPT 询问企业内部系统相关问题，常会出现这样的情况：它给出一段看似逻辑通顺、实则完全错误的回答。

LLM 的核心缺陷可归纳为三点：
- **训练数据存在时间截止日期**：GPT-4 的知识停留在训练完成的那一刻。
- **遇到知识盲区会产生"幻觉"**：不会如实回复"我不知道"，而是强行编造一段看似合理的回答。
- **无法识别企业私有知识**：内部文档、代码库、业务规则、团队约定不会出现在公开训练数据中。

**RAG（Retrieval-Augmented Generation，检索增强生成）**思路：让 LLM 先检索资料，再结合检索内容给出回答。

用户提问 → 检索相关的外部信息 → 把信息塞进 prompt → LLM 基于信息回答。这就把 LLM 从"闭卷考试"变成了"开卷考试"。

RAG 本质上做的是扩充 LLM 的推理上下文，检索的内容可以是任何来源：一份 PDF 文件、一段聊天记录、一条搜索结果、一个网页链接。

### 知识从哪来

RAG 要检索知识库，知识库里的知识分为两类：

**静态共享知识**：团队共享的、相对稳定的信息。
- 企业文档：飞书文档、Confluence、Notion、Google Docs 里的产品文档、技术方案、会议纪要、复盘报告
- 代码仓库：Git 仓库里的源码、README、API 文档、变更日志
- 聊天记录：Slack、飞书群聊、钉钉里的技术讨论
- 规章制度：HR 系统里的考勤规则、报销流程、假期政策

**动态个人记忆**：用户个人的偏好、习惯、历史行为。和文档"同一份内容对所有人可见"不同，记忆是"每位用户拥有专属独立存储"。

### RAG 的流水线

**离线阶段**：把知识库里的文档切成段落，每个段落用 Embedding 模型算一个向量，存进向量数据库。
文档 → 切段（Chunking）→ Embedding（向量化）→ 索引写入（存入向量库）

**在线阶段**：用户提问 → 问题向量化 → 向量搜索 Top-K 相关文档 → 把文档和问题一起塞给 LLM → LLM 生成答案。
Query Rewrite → Metadata Filter → Recall（ANN + BM25）→ RRF 融合 → Rerank 精排 → LLM 生成答案

RAG 好不好用，关键不在 LLM，而是在于"搜得准"。

## 二、Embedding：把文本变成可计算的数据

Embedding 做的事就是把文本变成向量，让语义相似度变成一个数学计算问题。

### 从"搜字面"到"搜意思"

传统数据库搜索就是字面匹配。用 SQL `LIKE '%编程语言%'` 搜："用户的编程语言是 Go"→ 命中，"用户写 Go 和 Python"→ 漏掉。

要让计算机理解"意思"，需要 Embedding（向量嵌入）。

### 什么是向量

向量就是一组有序的数字。主流 Embedding 模型常见的有 768、1024、1536 维。

`[3.0, 4.0]` 是二维向量，`[0.12, -0.34, 0.07]` 是三维向量。向量的价值在于可以用数学来比较——两个向量越"接近"，就说明它们代表的东西越相似。

在 RAG 里，"向量"指的是把文本转换后得到的一串浮点数：
`"用户喜欢川菜" → [0.21, -0.43, 0.07, 0.85, ..., -0.12] ← 1536 个数字`

文本变成向量之后，"这两句话意思像不像"就变成了"这两个向量距离近不近"——从语言问题变成了数学问题。

### 什么是 Embedding

Embedding 就是把一段文本变成向量空间中的一个点，背后是一个训练好的专用模型。模型通过对比学习（Contrastive Learning）训练——拉近正例（语义相关的文本对），推远负例（不相关的文本对），几十亿轮下来模型就内化了语言的语义关系。

**Embedding 模型 vs 大语言模型**：Embedding 模型做的是**压缩**——把一段文字的语义浓缩进一个向量；LLM 做的是**生成**——根据上下文一步步吐出文字。

### Dense vs Sparse：两种向量，两种能力

- **Dense（稠密向量）**：每个维度都有值。搜"数据库连接池"能命中"DB connection pool 配置"——文字完全不同，但意思一样。弱点是专有名词和编码不敏感。
- **Sparse（稀疏向量）**：只有少数维度有值，每个维度对应一个词。搜"SLB"精确命中所有含"SLB"的文档。弱点是换词就搜不到。

Dense 搜的是"意思"，Sparse 搜的是"字面"。一个好的搜索系统需要两者配合。

## 三、Chunking：知识怎么切

很多 RAG 项目效果差，根本原因不是 Embedding 模型不行，也不是向量库选错了，而是切块策略没做好。

### 为什么要切

1. Embedding 模型有输入长度上限（主流模型 512-8192 Token）
2. 即使模型能处理超长文本，语义稀释会让检索效果大打折扣——一篇 50 页文档讲了几十个功能点，Embedding 向量成了"平均值"
3. 即使检索回来了，送给 LLM 的内容也不该是整篇文档

### 切块策略

**固定长度切块 + 滑动窗口**：每 500 Token 一个 Chunk，Chunk 之间有重叠。滑动窗口让跨边界的句子至少能完整出现在某一个 Chunk 里。

**语义切块**：按文档的自然结构来切——标题、段落、小节。保持了每个 Chunk 的语义完整性，但需要文档本身有结构。

**Parent-Child Chunk**：Parent Chunk（大块，保留完整上下文） + Child Chunk（小块，用于检索）。检索时用 Child 去搜，返回时把 Parent 塞给 LLM。兼顾了召回率和上下文完整性。

### 总结
- 切太小丢上下文，切太大语义稀释
- 固定长度+滑动窗口是性价比最高的起点
- 控制好 Chunk 数量，把最相关的放在最前面或最后面（Lost in the Middle 现象）

## 四、相似度：怎么衡量"像不像"

**余弦相似度（Cosine Similarity）**：最主流的选择。比的是两个向量的方向有多接近。
`cos(θ) = (A · B) / (|A| × |B|)`，值域 [-1, 1]，1 表示方向完全一致。

为什么是余弦相似度？因为 Embedding 模型在训练时就是用余弦相似度来优化的。

**欧氏距离（Euclidean Distance）**：衡量两个点在空间中的直线距离，受向量长度影响大。

**点积（Dot Product）**：当向量已做 L2 归一化时，点积等于余弦相似度。

## 五、HNSW：从百万向量中快速找到最相似的

KNN（K-Nearest Neighbors）问题有两种解法：
- **精确 KNN**：逐条遍历所有向量，复杂度 O(N×D)
- **近似 KNN（ANN）**：用索引结构快速锁定候选区域，牺牲一点召回精度换数量级的性能提升

HNSW 是 ANN 里最主流的算法，融合了跳表（Skip List）和可导航小世界图（NSW）两种数据结构的核心思想。

**核心洞察**：在有序链表上增加多层"快速通道"。上层节点少、跨度大，底层包含全部节点。查找时从顶层一跳跨过大量元素，逐层缩小范围，复杂度从 O(n) 降到 O(log n)。

**三个关键参数**：
- M（每个节点的最大连接数）：越大召回率越高但内存和建图时间也越高
- efConstruction（建图时搜索范围）：越大图质量越高
- efSearch（查询时搜索范围）：越大召回越高但延迟也越高

## 六、检索的完整链路：从查询到精排

### Query Rewrite
用户提问不一定直击要害。常见的缺陷：指代不明（"它"指什么）、信息不足（"怎么退款"缺主体）、口语化表达（"那个上次说的问题"）。Query Rewrite 就是让 LLM 在检索前先改写问题。

### 元数据过滤
在向量检索之前加一道闸门。常见的元数据过滤维度：
- 时间范围：只搜最近三个月的文档
- 文档类型：只搜"技术方案"类文档
- 作者/部门：只搜本部门文档
- 文档状态：只搜"已发布"文档

元数据过滤在前端表现为"高级搜索"筛选项，在后端先走倒排索引过滤，大幅缩减检索范围。

### 两路互补：ANN（向量检索）+ BM25（关键词检索）
- ANN 负责语义匹配，BM25 负责精确匹配
- ANN 理解"意思"，BM25 抓住"字面"
- 融合策略：RRF（Reciprocal Rank Fusion）——不拼分数拼排名

BM25（Best Matching 25）是基于词频和文档频率的统计算法，是搜索引擎领域的经典打分公式（Lucene、Elasticsearch 的默认打分公式）。

### RRF：不拼分数拼排名
核心思想很简单：把 ANN 和 BM25 各自的排序结果，按排名位置融合。
`RRF(d) = 1/(k + rank_ANN(d)) + 1/(k + rank_BM25(d))`
k 是常数（通常 60），防止除零。分别排名，再相加排名倒数。排名越靠前，贡献越大。

### Rerank：粗筛之后，再精排一次
召回阶段用向量或关键词粗筛（速度优先），拿到一个较大的候选集（如 100-200 条），再交给 Rerank 模型（一个专门的 Cross-Encoder 模型）做精确的语义匹配排序。

Rerank 模型比 Embedding 模型更准但更慢——它会同时看 query 和文档内容做深度交互，不像 Embedding 只是分别算向量再比距离。

## 七、总结

RAG 系统的完整链路：Query Rewrite → Metadata Filter → Recall（ANN + BM25 两路）→ RRF 融合 → Rerank 精排 → 最终 LLM 生成。

核心要点：
1. **Embedding**：把语义变成可计算的向量，Dense + Sparse 互补
2. **Chunking**：好的切块策略是 RAG 效果的基石
3. **HNSW**：用可控的召回损失换数量级的性能提升
4. **两路检索**：语义匹配 + 关键词匹配互补
5. **Rerank**：粗筛后再精排，精度与效率的平衡点
6. **Query Rewrite**：用户不会提问怎么办——改写后再检索

RAG 好不好用的命门是"搜得准不准"。检索回来的东西不对，LLM 再强也是垃圾进垃圾出。
