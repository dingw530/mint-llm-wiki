OFFLINE FIRST
01

Mint 要解决什么问题？

普通聊天可以回答一次问题，却很难持续记住项目背景、知识来源和已经做过的决定。Mint 把这些内容放进一个可编译、可检索、可追溯的知识层，再让对话和 Agent 使用同一份上下文。

核心判断

如果上下文不能被留下、定位和继续使用，AI 的每次回答都可能只是一次性的文本生成。

02

从一个真实问题开始

不需要先理解所有模块。准备一份正在使用的项目资料，然后用一个具体问题走完下面的路径。

  1. 01
    放入资料

    导入 Wiki 页面、README、设计文档或会议记录，保留来源。

  2. 02
    检查知识状态

    查看页面、关系和知识热度，先知道哪些内容已经可用。

  3. 03
    在 Chat 中追问

    围绕一个问题逐步追问，并回到来源核对上下文。

  4. 04
    交给执行层

    需要行动时，再让 Agent 或 Tools 带着上下文完成下一步。

03

组件如何分工

Mint 不是把所有能力塞进一个聊天框。每一层有明确职责，也有明确的产出。

层负责什么产出什么
LLM Wiki积累、组织和编译知识可检索的页面、关系和来源
Context把相关内容带入当前任务有边界的上下文
Chat提供最低摩擦的交互入口问题、追问和回答
Agent / Tools根据上下文推进任务动作、结果和可回看的过程
04

06

知识信号是什么？

知识库不应该只是文件列表。访问、召回和关系可以成为反馈信号，帮助判断哪些页面正在被使用、哪些内容需要更新，以及下一次检索应该优先看到什么。

USE被谁使用

访问和召回反馈。

CARE哪里需要维护

过期、孤立或低热度页面。

NEXT下一步看什么

关系和检索优先级。
